# QA 결과

검증일: 2026-09-23. Windows, PHP 8.4.26, Chrome, Node v16.19.0. Node 테스트 런너는 해당 버전에서 experimental 경고를 표시하나 테스트는 통과.

## 자동 테스트

`tests/domain.test.js`: **12개 통과**.

1. 성공 거래만 합산, 성공 키 중복 방지
2. 실패 → 성공 재시도 동일 거래, 익명 설정
3. 종료/예정/금액 유효성, 초과 달성/목표액 0
4. 단체 보완/재제출/승인, 모금 심사/공개
5. 원거래 보존 환불, 순액 갱신, 중복 승인 차단
6. 약정 등록 분리, 결제일 이전 차단, 실패 재시도, 해지
7. 기업 매칭 별도 합산, 한도, 중복
8. 종료 → 지급 예정/승인/완료 → 보고 심사, 미집행 잔액
9. 신고 숨김, 처리 사유, 관리자 권한 분리
10. 모금 계획 합계/역할 검증
11. 재심사 수정안과 기존 공개본 분리
12. 한국 시간 월 경계와 짧은 달 처리

`tests/storage.test.js`: **3개 통과**.

- 첫 생성 시각 영속화/새로고침 동일값
- 손상 JSON 회복/경고
- 용량 초과 메모리 폴백/경고

수정 과정에서 Node 16의 structuredClone 미지원이 발견되어 JSON 데이터용 폴백을 추가하고 재검증했다. PHP 파일 **16개 문법 검사 통과**, 모든 자체 JS 모듈 문법 검사 통과.

## 실제 브라우저 확인

- 데모 로그인 → 익명/응원/10,000원 → 수단 → 결제 실패 → 입력 보존 → 성공 → 완료 → 새로고침 후 동일 완료 화면.
- 단체 신청 → 관리자 보완 요청 → 사유 표시 → 소개 수정 및 재제출 → 관리자 승인. (검증 당시 단체 센터 화면 기준)
- 모금 7단계: 기본→제목/사연→목표/기간→사용 계획→자료→미리보기→검토 요청. 승인 후 검색 ‘가을 식탁’에서 새 모금 카드 확인. (검증 당시 단체 센터 화면 기준)
- 사용자/마이페이지 **26 URL**, 관리자 **16 URL**, 단체/기업 **15 URL**: 직접 접근, 렌더 오류 없음, 360px에서 document 가로 넘침 없음. 표는 자체 스크롤.

> 단체 센터 `/partner/`와 기업 센터 `/corporate/`는 검증 이후 같은 날 정리 커밋에서 제거됐다. 위 두 흐름과 단체/기업 15 URL 결과, `partner-route-qa.json`은 제거 전 기록이며 현재 빌드에서는 재현되지 않는다. 관리자 심사 대기열은 초기 데이터의 검토 요청 항목(단체 1, 모금함 2, 결과보고 1, 환불 1)으로 채웠고, 신청·모금 작성·결과보고 규칙은 도메인 테스트 4·8·10·11번으로 계속 확인한다. 2026-09-23 재검증: 대시보드 건수 1/2/1/1, 단체·모금함·결과보고·환불 목록과 수정안 재심사 모달 렌더, `/donate/?status=ended`에 종료 모금 2건, 콘솔 오류 0건. 2026-09-24 관리자 정리: 표의 영문 원값을 한국어 라벨로 교체하고 배지 색을 팔레트 클래스로 매핑, 화면별 빈 상태 문구 적용. 콘텐츠 관리 폼을 유형별(공지·FAQ·스토리·모금 소식·홈 배너·추천 모금)로 분리해 추천 모금·FAQ 등록 → 관리자 표 → 홈 "지금 함께하면 좋은 나눔" 섹션과 고객센터 FAQ 노출까지 브라우저로 확인. 대시보드에 미답변 문의·신고 검토 대기 건수와 최근 문의·최근 신고 패널을 추가하고 1440·713·375px에서 가로 넘침 없음 확인. 검증 중 서로 다른 코드 버전의 탭 두 개가 schema 불일치로 저장소를 번갈아 덮어쓰는 무한 루프를 발견해, 더 새로운 schema는 덮어쓰지 않도록 저장소를 고치고 스토리지 테스트를 추가했다(총 16개).
- 사용자 검증 종료 시 Chrome 콘솔 오류 0건.
- 로컬 스톡 이미지 6종 로딩 완료. 이미지 오류 시 자체 fallback 제공.
- FAQ Enter로 열기(aria-expanded=true), ArrowDown으로 다음 제목 이동 확인. 데모 모달 Esc 닫힘 후 `demo-open` 버튼 초점 복귀 확인.
- 기부 내역 CSV 버튼 실행 및 다운로드 상태 안내 확인. Excel에서 파일 열기 검증은 별도.
- Native dialog/label/button/fieldset 대신 labelled radio, 스킵 링크, focus-visible 및 스크롤 표 tabindex 적용. 화면낭독기 전수 검수는 미실시.

검증 데이터: `public-route-qa.json`, `admin-route-qa.json`, `partner-route-qa.json`(제거된 화면의 과거 기록).

## 반응형

홈과 상세를 **1440, 1024, 768, 390, 360px**에서 캡처 및 scrollWidth 측정. 모든 구현 화면에서 document 넘침 없음.

| 뷰포트 | 홈 최대 콘텐츠 실측 | 카드 |
|---|---:|---|
| 1440 | 1160px | 4열, 각 272px |
| 1024 | 945px | 4열, 각 223.5px |
| 768 | 713px | 2열, 각 345.5px |
| 390 | 339px | 2열, 각 163.5px |
| 360 | 309px | 2열, 각 148.5px |

스크롤바 15px가 브라우저 viewport에 포함되어 계산됨. 모바일 상세 CTA는 하단 고정, safe-area와 body 여백 포함. 최종 시각 점검에서 상세 이미지의 HTML 높이가 모바일 비율을 덮는 문제를 찾아 height:auto로 수정했다.

## 한계 및 추가 검증 대상

- 모든 업무 흐름의 상태 계산은 자동 검증했지만, 12개 시나리오 전부의 모든 분기를 브라우저 클릭으로 전수 자동화한 것은 아니다. 실제 브라우저 전체 경로는 위 항목으로 구분했다.
- 결제 취소/처리 중·환불·매칭·지급·신고·정기 실패 재시도는 도메인 테스트와 연결 UI를 제공. 실제 PSP/은행/자동결제/공식 영수증은 의도적으로 미구현.
- CSV의 이스케이프·BOM 구현은 포함. 운영체제별 Excel 파일 열기, 스크린리더(NVDA/VoiceOver), 실제 모바일 터치 장치 전수 검증은 미실시.
- 다중 탭 동시에 같은 결제를 실행하는 경쟁 상태에 대해 서버 수준 ACID 보장을 제공하지 않음. API 연동 시 DB 트랜잭션과 멱등 unique 키 필요.
