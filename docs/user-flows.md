# 역할별 연결 시나리오

데모 설정에서 역할을 바꿔도 공통 데이터는 유지됩니다. 단체 센터와 기업 센터 화면은 2026-09-23에 제거됐으므로 신청·작성 단계는 초기 데이터가 대신하고, `submitOrganization`·`submitFund`·`submitImpact`의 검증 규칙은 `tests/domain.test.js`(4·8·10·11번)로 확인합니다. 초기 데이터의 검토 요청 항목: 단체 `org-4`(햇살동행, 검토 요청)와 `org-5`(바다지킴이, 보완 요청 사유 표시), 새 모금함 `fund-11`(시작일 미도래, 공개 전), 공개 중인 `fund-3`의 수정안(pending), 지급 완료된 `fund-10`의 결과보고, 회원 `user-2`의 환불 요청.

1. **단체 심사**: 관리자 `/admin/?view=organizations` → `햇살동행` 행의 심사 → 심사 시작 / 보완 요청 / 승인 / 반려와 사유. 심사 버튼은 submitted/reviewing 행에만 표시되며 보완 요청 행은 사유만 보인다.
2. **모금 공개**: 관리자 `/admin/?view=fundraisers` → `우리 동네 작은 도서관` 심사 승인 → 게시 상태 active. 시작일(기준 시각 +5일)이 지나야 사용자 목록에 공개되므로 데모 기준 시각을 이동해 확인. `유기견들의 든든한 울타리`는 수정안 재심사 예시로, 심사 모달에 "기존 공개본과 분리 저장됨"이 표시되고 승인 시 제목·목표액·사용 계획이 교체된다. 심사 중에도 기존 공개본으로 기부 가능.
3. **기부 성공**: 공개 모금 → 데모 로그인 → 금액, 익명, 메시지 → 수단 → 결과 성공 → 완료. 기부 내역, 모금 상세, 단체 현황, 관리자 거래에서 같은 거래를 조회.
4. **실패/취소**: 마지막 단계에서 결과 선택. 합산되지 않고 확인 화면에 상태 표시. 금액/공개/메시지 보존. 성공으로 재시도 가능.
5. **멱등성**: 결제 초안의 key를 새로고침·이전 이동에도 유지. 성공한 key로 재호출하면 기존 거래 반환. 새 기부를 시작하려면 완료 화면에서 ‘새 마음 전하기’를 사용.
6. **익명**: 공개 참여내역에는 ‘익명의 기부자’. 본인 마이페이지에는 금액·거래 ID·공개 설정 표시.
7. **정기**: `/monthly/`에서 약정 등록. 기부액은 증가하지 않음. 데모 설정 기준 시각을 다음 예정일 이후로 이동. `/my/?view=monthly`에서 회차 실패 후 재시도. 성공 내역 합산. 일시중지/재개/해지 가능.
8. **지급과 보고**: 종료된 `이웃과 나눈 따뜻한 식탁` → 관리자 `/admin/?view=payouts`에서 지급 예정 → 승인 → 지급 완료 데모. 결과보고 심사는 지급 완료된 `겨울방학 급식 지원 결과보고`(집행 2,850,000원)를 `/admin/?view=reports`에서 승인 → 상세 소식·결과보고 공개, 잔액 150,000원 표시. 결과보고 작성 화면은 없고 `submitImpact` 규칙은 도메인 테스트로 확인. 집행액은 지급액 이하이며 잔액 공개.
9. **기업 매칭**: 승인 캠페인의 기간 안에 직접 기부 성공 → 관리자 `/admin/?view=campaigns`에서 거래 선택 → 지원금 승인. 직접 기부와 별도 모델이며 동일 원거래 중복/한도 초과 차단.
10. **환불**: 본인 성공 거래 상세 → 사유 입력 → 관리자 환불 승인/반려. 승인 시 별도 refund 거래와 originalId 기록. 지급 절차가 시작된 모금은 이 데모에서 환불 제외.
11. **신고**: 회원으로 상세 댓글 신고 → 관리자 신고 검토 → 사유와 숨김 → 공개 댓글에서 제외, 본인은 숨김 상태 확인.
12. **탐색**: 필터는 URL query, 관심은 회원별 저장소. 브라우저 뒤로 가기로 목록 URL 유지, 데이터는 새로고침 후 유지.

금액 변경은 다음 미결제 회차부터 적용. 이미 실패한 회차는 해당 회차에 기록한 금액으로 재시도합니다. 성공한 회차만 다음 예정일을 생성합니다.
